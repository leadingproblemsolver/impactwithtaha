# Presentation references — 2026-09-14

The public surface should borrow **structure**, not visual identity or copy, from current high-signal portfolio systems.

## Patterns adopted

### Proof-first case architecture
Reference: Framer Kestrell
https://www.framer.com/marketplace/templates/kestrell/

Adopted pattern:
- a case should not publish without a visible result/receipt field;
- buyer/reviewer should not have to infer what happened;
- the site should move toward one consequential CTA rather than a generic project gallery.

### Two-speed reading
Reference: Framer Milo Ferris
https://www.framer.com/marketplace/templates/milo-ferris/

Adopted pattern:
- a hiring manager can scan identity, role fit, receipts and boundaries quickly;
- a technical reviewer can continue into source, mechanism, tests and detailed evidence.

### Signal ledger + case files
Reference: Framer Proofmark
https://www.framer.com/marketplace/templates/proofmark/

Adopted pattern:
- strongest proof points are visible before deep navigation;
- cases are structured as evidence files, not thumbnails;
- core signals (role, domains, working mode) remain compact;
- field notes/micro cases are downstream of real work rather than content for its own sake.

### Minimal case-study hierarchy
Reference: Framer Kelly Tokas
https://www.framer.com/marketplace/templates/kelly-tokas/

Adopted pattern:
- minimal navigation;
- typography does the prioritization work;
- problem / mechanism / impact / role / result remain visually distinct.

### Work itself as the interaction
Reference: Framer Motif Studio
https://www.framer.com/marketplace/templates/motif-studio/

Adopted pattern:
- the portfolio is not decoration around the work;
- interaction should expose the mechanism or proof whenever possible.

## Taha-specific translation

The site should not imitate a design portfolio.

Canonical theme:

`messy reality -> explicit state -> bounded intervention -> hostile verification -> external receipt`

Visual treatment should reinforce:
- inspectability;
- state;
- provenance;
- receipts;
- clear uncertainty;
- consequential next action.

Avoid:
- skill-cloud sections;
- generic testimonials without traceable context;
- inflated outcome metrics;
- project-card grids with no evidence boundary;
- personal-brand ornament that competes with proof.
