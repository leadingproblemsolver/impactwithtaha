# Test a Real Problem

**A free REF learning mini-workbook | October 2026 | Reader edition 1.0**
**Audience:** Student entrepreneurs, freelancers and new operators, 16+
**Learning outcome:** Verify a workflow pain and try the lightest safe intervention with a willing user.

## How to use this book
Read the short explanation, attempt its practice before checking the worked answer, then change the example and repeat from memory.

## 1. Ask about what happened

Speculative enthusiasm is not demand. Look for the task owner, actual failures, consequences and current workaround.

**Your practice:** Write discovery questions about missed appointments without pitching software.

**Worked example / answer check:** What was the last missed reminder? How did you notice? What did you do next?

**Transfer:** Try a new case from a different topic, without copying the example; write down what you checked.

## 2. Test a simple aid first

Use paper, blank templates or invented sample data before building a whole platform. Get permission to observe real work.

**Your practice:** A shop forgets callback requests. What can be tested without software?

**Worked example / answer check:** A blank call log with owner, task, date and status, using fictional or authorized examples.

**Transfer:** Try a new case from a different topic, without copying the example; write down what you checked.

## 3. Choose an observable measure

“Better productivity” is vague. Decide what safe pilot result would count as success and when to stop.

**Your practice:** Define a three-record test for the callback log.

**Worked example / answer check:** The consenting operator finds all three fictional requests without coaching; stop if private data is exposed.

**Transfer:** Try a new case from a different topic, without copying the example; write down what you checked.

## 4. Record the actual reaction

A compliment is not ongoing usage; a conversation is not a purchase. Observe whether the aid was used, rejected or revised.

**Your practice:** Write a response to a person who declined to keep using your prototype.

**Worked example / answer check:** “Thank you for testing. Which step caused extra work? I will record that limit and avoid assuming fit.”

**Transfer:** Try a new case from a different topic, without copying the example; write down what you checked.

## Independent challenge
Ask a willing operator about one bounded task and test one paper or sample-data aid; record exactly what happened.

Use this evidence card: **before / action / expected / observed / one limitation / next test**.

## Five-day practice
- Day 1: Try lesson one before reading its example answer.
- Day 2: Recall the core idea with notes closed; check and correct.
- Day 3: Try another lesson with a changed example.
- Day 4: Complete the independent challenge.
- Day 5: Show the result to a suitable reviewer and revise one step based on real feedback.
