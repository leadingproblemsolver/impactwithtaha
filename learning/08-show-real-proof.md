# Show Real Proof

**A free REF learning mini-workbook | October 2026 | Reader edition 1.0**
**Audience:** Students and first-job applicants, 16+
**Learning outcome:** Create a source-linked portfolio case study without inflated achievements.

## How to use this book
Read the short explanation, attempt its practice before checking the worked answer, then change the example and repeat from memory.

## 1. Use exact achievement labels

A local prototype is not a production deployment; an open PR is not a merged contribution. All are useful with accurate descriptions.

**Your practice:** Rewrite “enterprise product” when the evidence is only a local prototype.

**Worked example / answer check:** “Built and tested a local prototype; no confirmed production or customer use.”

**Transfer:** Try a new case from a different topic, without copying the example; write down what you checked.

## 2. Expose the execution path

Make it easy to inspect problem, input, steps, output, tests and limitations. A lone repository link may not be enough.

**Your practice:** Write a four-line README for a duplicate-row checker.

**Worked example / answer check:** Describe sample CSV input, run command, expected duplicate warning and untested file formats.

**Transfer:** Try a new case from a different topic, without copying the example; write down what you checked.

## 3. Document failures accurately

Distinguish observed errors from suspected causes and verified fixes. An unresolved reproducible defect still communicates useful work.

**Your practice:** Rewrite “my provider broke the deployment” when only logs are known.

**Worked example / answer check:** “Deployment failed; logs mention a missing environment variable. A fix has not yet been confirmed.”

**Transfer:** Try a new case from a different topic, without copying the example; write down what you checked.

## 4. Seek role-specific review

Choose a reviewer who cares about the capability shown. Ask them to try a specific reproduction step.

**Your practice:** Write a technical feedback request.

**Worked example / answer check:** “Could you try the steps and tell me the first point that fails or feels ambiguous?”

**Transfer:** Try a new case from a different topic, without copying the example; write down what you checked.

## Independent challenge
Write one proof card: problem, build, reproducible test, actual result, limitations, reviewer question.

Use this evidence card: **before / action / expected / observed / one limitation / next test**.

## Five-day practice
- Day 1: Try lesson one before reading its example answer.
- Day 2: Recall the core idea with notes closed; check and correct.
- Day 3: Try another lesson with a changed example.
- Day 4: Complete the independent challenge.
- Day 5: Show the result to a suitable reviewer and revise one step based on real feedback.
